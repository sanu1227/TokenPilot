# TokenPilot 개발 기록



TokenPilot의 개발 목표, 변경 사항, 설계 결정, 검증 결과를 날짜순으로 기록한다. API 키, 비밀번호, 쿠키 등 민감 정보는 기록하지 않는다.

## 2026-09-20 - Android 개발 환경 초기 구성

### 목표

- TokenPilot Android 개발을 시작할 수 있는 로컬 환경을 구성한다.
- 이후 모든 개발 작업을 누적 기록할 문서를 만든다.

### 변경 사항

- Android Studio Quail 4 `2026.1.4`를 설치했다.
- Android SDK command-line tools, Platform Tools, Android 36·37 플랫폼, Build Tools 36을 설치했다.
- Kotlin과 Jetpack Compose 기반 단일 앱 모듈을 생성했다.
- 최소 실행 화면에 TokenPilot 이름과 개발 환경 준비 상태를 표시했다.
- 프로젝트 사용법을 `README.md`에 기록했다.
- 프로젝트 작업 규칙을 `AGENTS.md`에 추가했다.

### 설계 결정

- 공식 Android CLI의 `empty-activity` 템플릿을 기반으로 구성했다.
- 초기 호환성과 단순성을 위해 `minSdk 26`, `compileSdk 36`, `targetSdk 36`을 사용한다.
- 사용하지 않는 Navigation, ViewModel, 직렬화, 테스트 의존성은 초기 구성에서 제외했다.
- 에뮬레이터와 시스템 이미지는 용량이 크므로 첫 UI 실행 검증 단계에서 추가한다.

### 검증

- Android Studio와 포함 JDK의 설치 상태를 확인했다.
- Android SDK 라이선스 동의와 필수 패키지 설치를 확인했다.
- `gradlew.bat assembleDebug`가 성공했다.
- `app/build/outputs/apk/debug/app-debug.apk` 생성을 확인했다.
- `gradlew.bat test`가 성공했다. 현재 테스트 소스는 없어 실행된 테스트는 없다.
- `gradlew.bat lintDebug`가 경고나 오류 없이 성공했다.

### 남은 확인 사항

- 실제 기기 또는 에뮬레이터 실행 여부
- Codex 구독 사용량을 로컬에서 읽을 수 있는지에 대한 기술 검증

## 2026-09-20 - 수동 사용량 관리 첫 구현

### 목표와 작업 범위

사용자가 실제 값을 등록하고 다시 확인할 수 있는 Android 단독 기능을 구현한다. 자동 연동을 기다리지 않고 입력, 보관, 일정 확인이라는 기본 흐름을 검증한다. 이 단계는 전체 MVP 완료를 의미하지 않는다.

### 파일별 변경

- `app/src/main/java/com/tokenpilot/app/MainActivity.kt`: 초기 안내 화면을 홈, 초기화, 설정의 세 탭으로 교체했다. 등록·수정 대화상자, 서비스·제한 구간 선택 메뉴, 삭제 확인 대화상자를 추가했다.
- `app/src/main/java/com/tokenpilot/app/Usage.kt`: 서비스 이름, 제한 구간, 잔여 비율, 초기화 시각, 확인 시각을 담는 Usage 모델을 추가했다. 날짜 파싱, 비율 검증, 남은 시간 표시를 UI에서 분리했다.
- `app/src/test/java/com/tokenpilot/app/UsageTest.kt`: 날짜, 비율 경계, 초기화 경계, 일광절약시간에 대한 네 개의 단위 테스트를 추가했다.
- `gradle/libs.versions.toml`, `app/build.gradle.kts`: JUnit 4.13.2를 테스트 전용 의존성으로 추가했다. Gradle이 다운로드하며 실제 배포 앱에는 포함되지 않는다.
- `app/src/main/AndroidManifest.xml`: 기본 자동 백업을 비활성화했다. 제조사별 기기 이전 정책까지 검증한 것은 아니다.
- `README.md`: 현재 기능, 날짜 입력 방법, 검증 명령을 추가했다.
- `AGENTS.md`: 사용자 설명은 쉽게 요약하고 개발 기록은 파일별 변경과 검증 한계를 상세히 남기도록 규칙을 추가했다.

### 화면과 입력 동작

1. 홈의 사용량 등록 버튼을 누른다.
2. Codex, Claude, Gemini, Grok 중 하나를 선택한다.
3. 5시간, 세션, 일간, 주간 중 사용자가 실제 확인한 제한 구간을 선택한다. 모든 서비스가 모든 구간을 공식 지원한다는 뜻은 아니다.
4. 잔여 비율과 초기화 시각을 입력한다. 날짜 형식은 `yyyy-MM-dd HH:mm`이며 현재 기기 시간대를 사용한다.
5. 저장하면 카드가 나타난다. 카드에는 마지막 입력 잔여량, 예정 시각, 확인 시각, 수동 입력 출처가 표시된다.
6. 같은 서비스의 같은 제한 구간은 중복 등록할 수 없다. 기존 카드에서 수정한다.
7. 초기화 탭에서는 기록을 초기화 시각 오름차순으로 정렬한다.
8. 삭제는 확인 대화상자에서 확정한 경우만 수행한다.

### 데이터 저장과 오류 처리

- 앱 전용 SharedPreferences `usage`의 `records` 키에 JSON 배열로 저장한다.
- 한 기록은 `service`, `window`, `percent`, `reset`, `updated` 필드를 가진다.
- 시간은 epoch millisecond로 저장하고 표시할 때 기기 시간대로 변환한다.
- 소량의 수동 기록에 맞춰 기존 Android 저장 기능을 사용했다. 별도 데이터베이스 의존성은 추가하지 않았다.
- 시작 시 JSON 파싱과 서비스·구간·비율 검증을 수행한다. 읽기 실패 시 빈 화면에 오류 안내를 표시하고 편집을 막아 원본 데이터가 덮어써지지 않게 한다.
- 저장은 `apply()`로 요청한다. 디스크 쓰기 실패를 사용자에게 보고하는 기능은 아직 없다.
- 인증 정보나 대화 내용은 수집하지 않는다. 이번 저장소에 있는 값은 사용자가 직접 입력한 사용량 메타데이터이다.

### 시간 계산과 경계 조건

- 비율은 정수 0~100만 허용한다. 소수, 음수, 범위 초과, 비숫자는 거부한다.
- 날짜 파싱은 STRICT 모드를 사용해 2월 30일 같은 잘못된 날짜를 거부한다.
- 초기화 시각은 저장 시점의 현재 시각보다 이후여야 한다.
- 일광절약시간 변경으로 존재하지 않거나 두 번 존재하는 지역 시각은 거부한다.
- 화면에서 현재 시각을 15초 간격으로 갱신한다. 백그라운드 예약 알림 기능은 아니다.
- 남은 시간은 분 단위로 올림한다. 예정 시각을 지나면 재확인 필요 문구를 보여준다.
- 예정 시각이 지났다고 잔여 비율을 자동으로 100%로 변경하지 않는다. 마지막 입력값을 유지한다.

### 검증 및 한계

- 실행 명령: `gradlew.bat assembleDebug testDebugUnitTest lintDebug --console=plain`.
- 첫 실행에서 빌드 성공, 단위 테스트 4개 성공(실패 0, 오류 0)을 확인했다.
- 검사에서 버전 카탈로그 사용 권고가 나와 JUnit 선언을 카탈로그로 이동했다.
- 최종 변경 후 같은 검증 명령을 다시 실행해 33초 만에 성공했다. 테스트는 4개 통과했으며 최종 Lint 결과는 오류 0개, 경고 11개이다. APK는 `app/build/outputs/apk/debug/app-debug.apk`에 생성됐다.
- Android Lint는 실행 성공과 경고 없음이 다르다. 앞선 초기 환경 기록의 “경고나 오류 없이”라는 표현은 정확하지 않았으며, 현재 보고서에는 SDK/라이브러리 업데이트 및 템플릿 리소스 관련 권고 등이 존재한다.
- `adb devices`에서 연결 기기가 없었다. 실제 기기 화면, 터치 동작, 프로세스 종료 후 저장 복구는 이번 작업에서 실행 검증하지 못했다.
- 에뮬레이터 설치나 시스템 가상화 설정 변경은 이번 단계에 포함하지 않았다.

### 남은 작업

- 입력 중 화면 회전 시 편집 상태 보존과 접근성·큰 글꼴 화면 검증.

- 날짜·시간 선택기를 이용한 입력 편의 개선.

- 업데이트 소식 기능과 기획 시안의 상세 디자인 적용.

## 2026-09-21 - PC 에뮬레이터 설치 및 앱 실행

### 목표

PC의 가상 휴대폰에서 현재 TokenPilot 앱을 사용자가 직접 확인할 수 있도록 한다.

- 별도 에뮬레이터 창으로 기기를 실행했다. Android Studio에서 Device Manager를 통해 같은 가상 기기를 다시 실행할 수 있다.

### 검증

- 가상 기기 생성 과정에서 devices.xml 읽기 오류 문구가 있었지만 AVD 생성 및 실행은 성공했다.

- `adb install -r`로 기존 디버그 APK를 설치했다.
- `am start -W -n com.tokenpilot.app/.MainActivity` 결과 Status: ok, COLD 실행, 약 3.4초였다.
- Android의 topResumedActivity가 TokenPilot임을 확인했다.
- `docs/emulator-launch.png`에 화면을 저장하고 직접 확인했다. 앱 제목, 사용량 등록 버튼, 빈 기록 안내, 홈·초기화·설정 탭이 표시됐다.

### 남은 확인 사항

- 이번 검증은 설치와 초기 화면 실행까지다. 등록·수정·삭제 및 재시작 후 데이터 복구의 전체 상호작용 테스트는 별도 진행한다.

## 2026-09-29 - Codex 자동 사용량 조회 기술 검증 성공

### 목표와 결정

- Codex부터 완성하고 다른 AI는 이후 확장한다는 사용자 방향을 적용했다.
- 이번 단계는 실제 구독 한도 자동 조회를 검증하고 재실행 가능한 PC 도구를 남기는 범위다.
- 공식 App Server 문서 https://learn.chatgpt.com/docs/app-server 에서 account/rateLimits/read와 각 응답 필드 의미를 확인했다.
- 이전 기획의 공개 연동 경로 미확인 상태를 갱신한다. 현재 공식 문서에 조회 메서드가 존재하고 로컬 CLI에서 동작했다.

### 구현

- companion/codex-usage.mjs: Node 표준 라이브러리만으로 Codex app-server 자식 프로세스를 실행하고 stdio JSON 메시지를 교환한다.
- initialize 응답을 기다린 후 initialized 알림을 보내고 account/rateLimits/read를 요청한다. 요청 ID별 응답을 매칭하고 기타 알림은 무시한다.
- 복수 한도 응답을 우선 사용하고 구형 단일 한도 응답을 대체 경로로 지원한다.
- usedPercent를 100에서 빼 잔여량으로 변환하고 0~100으로 제한한다. 미제공 값은 null을 유지한다.
- 구간 길이는 응답 분 단위를 유지한다. 5시간이나 주간이라는 가정을 조회기에 고정하지 않았다.
- 초기화 시각은 Unix 초로 유지한다. Android 연결 시 밀리초 변환이 필요하다.
- 30초 시간 초과, 실행 실패, 통신 실패, RPC 실패를 처리하고 자체 시작한 프로세스를 정리한다.
- 인증 파일, 쿠키, 비밀번호를 직접 읽지 않는다. 전체 RPC 응답이나 stderr를 기록하지 않고 허용한 사용량 필드만 출력한다.
- 서버 포트, 방화벽 변경, 새로운 라이브러리 설치는 필요하지 않았다.

### 검증

- 로컬 버전: codex-cli 0.158.0-alpha.2.1.
- node --test companion/codex-usage.test.mjs: 3개 통과, 실패 0.
- 복수 구간 우선 처리, 잔여 비율 변환, 초기화 초 단위 보존, 누락값, 범위 초과값, 실행 파일 누락 오류를 검증했다.
- node companion/codex-usage.mjs 실계정 실행 성공. 2026-09-29 05:11:10 UTC 조회 시 300분 구간 잔여 79%, 10080분 구간 잔여 75%를 반환했다. 두 구간 모두 초기화 시각을 받았다.
- 이 숫자는 해당 시점의 스냅샷이며 최신 상태를 의미하지 않는다.
- 모델 작업이나 사용자 대화 요청, 초기화 크레딧 소비 메서드는 호출하지 않았다.

### 남은 작업

- Android 앱으로 전달하는 연결과 자동 갱신은 아직 구현하지 않았다. 현재 APK는 수동 관리 버전이다.
- 다음 단계에서 PC 조회 결과를 Android에 연결하고 출처·확인 시각·오래된 상태를 구분한다.
- 실제 휴대폰 연결은 페어링과 전송 보호를 설계해야 한다. Codex app-server 자체를 외부 네트워크에 그대로 공개하지 않는다.
- CLI가 alpha 버전이므로 향후 변경에 대비한 호환성 확인이 필요하다.

## 2026-09-29 - Codex 자동 조회를 Android 에뮬레이터에 연결

### 목표 및 완료 범위

PC의 실제 Codex 구독 사용량을 Android에 전달하고 홈에서 자동 표시한다. 현재 개발 환경의 에뮬레이터와 ADB USB 연결을 대상으로 구현했다. LAN·인터넷 연결이나 백그라운드 알림까지 완료한 것은 아니다.

### 파일별 구현

- `companion/server.mjs`: Node 표준 HTTP 서버 추가. 127.0.0.1:18745에만 바인딩하고 GET /usage만 제공한다. 기존 readUsage를 호출하며 55초 캐시 및 진행 중 요청 공유로 중복 조회를 줄였다.
- 서버는 Origin 헤더가 있는 브라우저 요청 및 loopback이 아닌 Host를 거부한다. 별도 인증 서버는 아니며 로컬 PC 프로세스의 접근은 허용된다. 인터넷 포트나 방화벽 규칙을 추가하지 않았다.
- 조회 오류는 상세 내부 정보 없이 503으로 전달한다. 실패한 조회를 정상 잔여량으로 만들지 않는다.

- 알림은 실제 초기화 완료를 단정하지 않는다. 저장된 예정 시각 도달 안내이며 최신 잔여량은 앱에서 다시 조회해야 한다.
- 사용량 표시도 마지막 조회값으로 명시한다. 앱을 닫은 상태에서 사용량을 자동 갱신하는 서비스는 아직 없다. 예정 시각이 지난 값을 자동으로 100%로 바꾸지 않는다.
- 알림 스위치 해제 시 표시 알림 또는 초기화 예약을 제거한다. Android 강제 종료는 예약을 지울 수 있으므로 다음 앱 재개 시 복원한다.
- Android 버전에 따라 ongoing 알림도 사용자가 지울 수 있다. 잠금화면 내용은 PRIVATE로 표시하고 개별 채널의 차단·소리는 OS 설정을 따른다.
- 약 10초 후 테스트는 별도 action/notification ID를 사용하며 실제 조회값·예약 시각을 바꾸지 않는다.
